Token

…

Bridge session token. Take the contents of the file ~/sidekick/bridge/hub/token on the Hermes machine (one line, no newline) and paste it here. It is stored only locally in the extension; the value is never shown on the page.

Bell

"Check bell" issues a live system notification with sound — the same path as the agent's bell (a valid icon from icons/, no data: URIs). The sound comes from the operating system: WebExtensions has no audio API. On macOS — System Settings → Notifications → Firefox → "Allow Notifications" and "Sounds". The task-done popup appears only when the Firefox window is not focused; permissions always ring.

  • Firefox: Settings → Privacy & Security → Notifications — the extension must not be in "Block".
  • macOS: System Settings → Notifications → Firefox → "Allow Notifications".
  • macOS: enable "Sounds" in the same place — the sound is macOS's, the extension has none.
  • You see nothing while the window is focused — that is by design for tasks: the bell badge and the journal. "Check bell" forces a popup.

Server

…

WS address of the Hermes bridge. Empty = ws://127.0.0.1:8791 — the ssh-tunnel mode, as before. To connect over the local network without ssh, set the address of the machine with the bridge, e.g. ws://host-a.local:8791; the bridge must then listen on SIDEKICK_BIND=0.0.0.0 (the bridge systemd unit). If the given address is unavailable, the extension falls back to localhost (tunnel) by itself, and retries ramp up exponentially from 2 to 60 seconds.

ws:// carries the token in clear text over the network — trusted home network only; for everything else keep the tunnel (empty field).
